## A. WPF / WPF-UI 控件

### A1 ⚠️ `NavigationView` 塞不进内容

**现象**
```xml
<ui:NavigationView>
  <Grid>...</Grid>          <!-- MC3028: 无法向 NavigationView 类型的对象添加内容 -->
</ui:NavigationView>
```

**根因**：`ui:NavigationView` 的基类是 **`Control`**，不是 `ContentControl`，没有 `Content` 属性。

**修法**：内容放 `ContentOverlay`
```xml
<ui:NavigationView>
  <ui:NavigationView.ContentOverlay>
    <Grid>...</Grid>
  </ui:NavigationView.ContentOverlay>
</ui:NavigationView>
```

**怎么查清楚的**：PowerShell 5.1 加载不了 .NET 8 程序集，所以建了个 `net8.0-windows` 的探针工程反射 `Wpf.Ui.dll`：
```powershell
# wpf-probe\Program.cs
var t = typeof(Wpf.Ui.Controls.NavigationView);
Console.WriteLine(t.BaseType.Name);   // → Control
```
**这个探针工程很有用，建议保留。**

### A2 `NavigationViewItemHeader` 不认 `Content`

**现象**：`MC3074: 命名空间不存在标记"Content"` 之类的报错。

**根因**：`NavigationViewItemHeader` 的属性叫 **`Text`**，不是 `Content`。

**修法**：`<ui:NavigationViewItemHeader Text="运维" />`

### A3 `CardControl` 行为怪异

**根因**：`ui:CardControl` 继承 **`ButtonBase`** —— 它是个**可点击的卡片**，不是容器。

**修法**：纯粹当容器用 `ui:Card`（它是 `ContentControl`）。

**一句话区分**：
| 控件 | 基类 | 用途 |
|---|---|---|
| `ui:Card` | `ContentControl` | 容器 |
| `ui:CardControl` | `ButtonBase` | 可点击的卡片 |
| `ui:CardExpander` | `Expander` | 可展开的卡片 |

### A4 ⚠️ 主题切换点了没反应

**现象**：左下角「深色模式」点了什么都不发生。

**根因**：**`NavigationView.SelectionChanged` 对 `FooterMenuItems` 不触发**。

**修法**：`NavigationViewItem` 继承 `ButtonBase`，所以给**每个 item 单独挂 `Click`**：

```xml
<ui:NavigationViewItem Content="深色模式" Tag="theme" Click="NavItem_Click" />
```

```csharp
private void NavItem_Click(object sender, RoutedEventArgs e)
{
    var nvi = sender as NavigationViewItem;
    string tag = nvi.Tag as string;
    if (string.IsNullOrEmpty(tag)) return;      // 分组项，只展开/收起
    if (tag == "theme") { ToggleTheme(); return; }
    ...
}
```

### A5 `ui:ProgressBar` 不存在

**现象**：`MC3074: 命名空间不存在标记"ProgressBar"`

**根因**：WPF-UI 4.x **没有** `ui:ProgressBar`。

**修法**：不确定进度用 `ui:ProgressRing`；确定进度用标准 `System.Windows.Controls.ProgressBar`。

### A6 ⚠️⚠️ 抽屉收起后留一大片空白（三个坑叠加）

**这条最坑，三个独立问题叠在一起，我修了三轮。**

#### 第 1 层：`CardExpander` 的 `Expanded`/`Collapsed` 事件不触发

```xml
<ui:CardExpander Expanded="ExpLog_Expanded" Collapsed="ExpLog_Collapsed">
<!-- 编译通过，但事件永远不触发 -->
```

**修法**：用 `DependencyPropertyDescriptor` 监听 `IsExpanded` 属性变化：

```csharp
DependencyPropertyDescriptor dpd = DependencyPropertyDescriptor.FromProperty(
    CardExpander.IsExpandedProperty, typeof(CardExpander));
dpd.AddValueChanged(ExpLog, delegate { LayoutDrawers(); });
dpd.AddValueChanged(ExpIp,  delegate { LayoutDrawers(); });
```

> `DependencyPropertyDescriptor` 在 `System.ComponentModel` 命名空间。

#### 第 2 层：⚠️⚠️ `ElementName` 绑定在 `Grid.RowDefinitions` 里**静默失败**

```xml
<Grid.RowDefinitions>
  <RowDefinition Height="{Binding IsExpanded, ElementName=ExpLog, Converter={StaticResource ExpHeight}}" />
  <!-- 编译通过，不报错，但绑定永远不生效，Height 退回默认值 * -->
</Grid.RowDefinitions>
```

**根因**：`RowDefinition` **不在可视化树上**，`ElementName` 解析不到名字。

**修法**：**不要在 RowDefinition 上用 ElementName 绑定**。改成在代码后置里直接设：

```csharp
RowLog.Height = logOpen ? new GridLength(1, GridUnitType.Star) : GridLength.Auto;
```

#### 第 3 层：⚠️⚠️⚠️ `CardExpander` 默认 `VerticalAlignment = Center`

**这条是最终元凶。**

**现象**：行高明明设对了，卡片还是只在行里占一小块，剩下全是空白。

**怎么查出来的**：往 `%TEMP%\vrctool-dbg.txt` 写调试日志，打印 `ActualHeight` / `DesiredSize` / `VerticalAlignment`：

```
log=False (已收起)  ExpLog.Act=185.6  ExpLog.Des=185.6  ExpLog.Vert=Center
                    TxtLog.Vis=Visible  TxtLog.Des=118.4
```

两个发现：
1. 收起后 `DesiredSize` 仍是 **185.6**（不是标题栏高度）→ `Height=Auto` 会算出 185，留一大片空白
2. **`Vert=Center`** → 卡片在行里垂直居中，行里剩下的空间全变空白

**手算验证**：行 412px，卡片 155px，居中后起始位置 = 517 + (412−155)/2 ≈ 645 —— **正好等于截图里卡片的实际 y 坐标**。

**修法**：
```xml
<ui:CardExpander x:Name="ExpLog" VerticalAlignment="Stretch" ... />
<ui:CardExpander x:Name="ExpIp"  VerticalAlignment="Stretch" ... />
```

#### 配套：外层 Grid 要加「弹性空白行」

不然两个都收起时，底部按钮和进度条会跟着上浮。

```xml
<RowDefinition x:Name="RowDrawers" Height="*" />    <!-- 4 抽屉区 -->
<RowDefinition x:Name="RowSlack"   Height="Auto" /> <!-- 5 弹性空白 -->
<RowDefinition Height="Auto" />                     <!-- 6 底部按钮 -->
<RowDefinition Height="Auto" />                     <!-- 7 进度条 -->
```

```csharp
RowDrawers.Height = any ? new GridLength(1, GridUnitType.Star) : GridLength.Auto;
RowSlack.Height   = any ? GridLength.Auto : new GridLength(1, GridUnitType.Star);
```

**最终效果**：两个都收起 → 两个标题栏紧凑堆叠，其余空间给 `RowSlack`，底部控件钉在底部。

**教训**：**看截图下结论要谨慎。** 我第 2 轮看到"另一个抽屉出现在下方"就以为修好了，其实中间还有 130px 空白。**量数据，别猜。**

### A7 ⚠️ 弹窗按钮看起来"自制"

**现象**：用户说"按钮的原生控件风格还是不对，这个一看就是你自己做的"。

**根因**：我手写了一堆尺寸覆盖，把 WPF-UI 的原生样式盖掉了：
```xml
<!-- 错的 -->
<ui:Button Height="48" FontSize="14.5" Padding="16,0" HorizontalAlignment="Stretch">
  <StackPanel Orientation="Horizontal">
    <ui:SymbolIcon Symbol="Play24"/><TextBlock Text="开始执行"/>
  </StackPanel>
</ui:Button>
```

**修法**：**全部交回原生属性**
```xml
<ui:Button Appearance="Primary" Icon="{ui:SymbolIcon Play24}" Content="开始执行"/>
```

文字用 `ui:TextBlock` 的 `FontTypography`（Fluent 排版等级）：

| 用途 | `FontTypography` |
|---|---|
| 页面标题 | `Title` |
| 小标题 | `Subtitle` / `BodyStrong` |
| 正文 | `Body` |
| 辅助文字 | `Caption` |

**原则：不要写 `Height` / `FontSize` / `Padding`，让控件自己决定。**

### A12 导航项没有选中高亮

**现象**：不用 `Frame` 导航时，`NavigationView` 不画选中指示。

**修法**：手工设 `IsActive`，而且要**递归**（分组有子项）：
```csharp
private void HighlightNav(int idx)
{
    foreach (object o in RootNav.MenuItems) WalkHighlight(o, idx);
    foreach (object o in RootNav.FooterMenuItems) WalkHighlight(o, idx);
}

private void WalkHighlight(object o, int idx)
{
    var nvi = o as NavigationViewItem;
    if (nvi == null) return;
    int tagVal;
    bool isLeaf = int.TryParse(nvi.Tag as string, out tagVal);
    nvi.IsActive = isLeaf && (tagVal == idx);        // 分组项不参与
    foreach (object c in nvi.MenuItems) WalkHighlight(c, idx);
}
```

## B. 提权 / 自动化

### B1 ⚠️ 提权的 cmd 窗口挡住点击

**现象**：用 `fodhelper` 提权跑命令时，弹出个控制台窗口，挡在前面导致后续的鼠标点击全打在它身上。

**修法**：用 VBS 隐藏窗口启动
```vbs
' hid.vbs
CreateObject("WScript.Shell").Run WScript.Arguments(0), 0, True
```
```powershell
Set-ItemProperty $key '(Default)' "wscript.exe `"$env:TEMP\hid.vbs`" `"cmd.exe /c $inner`""
```

**完整提权通道**：
```powershell
function Invoke-ElevatedHidden {
    param([string]$RunCmd, [int]$Wait = 10)
    $inner = "$env:TEMP\_eh.cmd"
    [IO.File]::WriteAllText($inner, $RunCmd + "`r`n", (New-Object System.Text.ASCIIEncoding))
    $key = 'HKCU:\Software\Classes\ms-settings\Shell\Open\command'
    try {
        New-Item -Path $key -Force | Out-Null
        Set-ItemProperty -Path $key -Name '(Default)' -Value "wscript.exe `"$env:TEMP\hid.vbs`" `"cmd.exe /c $inner`""
        Set-ItemProperty -Path $key -Name 'DelegateExecute' -Value ''
        Start-Process "$env:SystemRoot\System32\fodhelper.exe" -WindowStyle Hidden
        Start-Sleep -Seconds $Wait
    } finally {
        Remove-Item 'HKCU:\Software\Classes\ms-settings' -Recurse -Force -EA SilentlyContinue
        Get-Process fodhelper -EA SilentlyContinue | Stop-Process -Force -EA SilentlyContinue
    }
}
```
> ⚠️ **必须在 finally 里清理注册表项**，否则残留会污染用户的文件关联。

**注意**：反病毒开启时 `fodhelper` 会被拦（报 `配对的某个文件被删除` 之类）。当前 AV 是关的。

### B3 ⚠️⚠️ 自动点击一直失败（DPI 虚拟化）

**现象**：`SetCursorPos(1025, 640)` 报告"已点击"，但目标按钮毫无反应。

```powershell
[HardClick]::Activate()                       # ShowWindow(9) + BringWindowToTop + SetForegroundWindow
[HardClick]::WhatAt($x, $y)                   # 调试：这个坐标上是哪个窗口
[HardClick]::Click($x, $y)
```

**仍未解决**：`开始安装` 按钮（详见 `ISSUES.md` #3）。

**另一个坑**：UI Automation 从**非提权进程**查**提权窗口**的子元素，会返回空 —— UIPI 拦截。要查必须从提权进程查。

### C4 `ProductName` 还是 `MicaApp`

**现象**：安装包右键属性显示 `ProductName: MicaApp`、`CompanyName: Lemutec`。

**根因**：这些在 MicaSetup 的安装器模板里是**硬编码**的：
```csharp
// .dist\Program.cs / Program.un.cs
[assembly: AssemblyTitle("MicaApp Setup")]
[assembly: AssemblyProduct("MicaApp")]
[assembly: AssemblyDescription("MicaApp Setup")]
[assembly: AssemblyCompany("Lemutec")]
[assembly: AssemblyCopyright("Under MIT License. Copyright (c) Lemutec Contributors.")]
```
makemica **只改写** `Guid` / `AssemblyVersion` / `AssemblyFileVersion` / `RequestExecutionLevel` 和 `UseOptions` 那个 lambda，**不碰** `AssemblyProduct` / `AssemblyTitle` / `AssemblyCompany`。

**修法**：在构建脚本里，makemica 生成 `.dist` **之后、编译之前**，自己替换：

```powershell
$pairs = @(
    @('[assembly: AssemblyProduct("MicaApp")]', "[assembly: AssemblyProduct(`"$AppName`")]"),
    @('[assembly: AssemblyCompany("Lemutec")]', "[assembly: AssemblyCompany(`"$Publisher`")]"),
    ...
)
foreach ($f in @('Program.cs', 'Program.un.cs')) {
    $fp = Join-Path $DistDir $f
    $t = [IO.File]::ReadAllText($fp, [Text.Encoding]::UTF8)
    foreach ($pr in $pairs) { $t = $t.Replace($pr[0], $pr[1]) }
    [IO.File]::WriteAllText($fp, $t, (New-Object Text.UTF8Encoding($true)))
}
```

**顺带**：`option.KeyName` / `AppName` / `ExeName` / `Publisher` 也在 `Program.cs` 里，一并改。

### C7 ⚠️ PowerShell 5.1 把无 BOM 的 UTF-8 当 ANSI 读

**现象**：中文变成乱码 `浼橀€夊伐鍏?`，然后**解析器报语法错误**。

**根因**：用外部工具（`write` 之类）写 `.ps1` / `.json` 时默认是**无 BOM UTF-8**，PS 5.1 按 ANSI 解码。

**修法**：写完加 BOM
```powershell
$t = [IO.File]::ReadAllText($f, [Text.Encoding]::UTF8)
[IO.File]::WriteAllText($f, $t, (New-Object Text.UTF8Encoding($true)))   # $true = 带 BOM
```

**例外**：`micasetup.json` 要**无 BOM**（`New-Object Text.UTF8Encoding($false)`），因为 JSON 解析器对 BOM 敏感。

### C8 ⚠️ 注入源文件被 C# 通配符扫进去

**现象**：把 `EnvCheckHelper.cs` 放到 `wpf\setup\inject\`，`dotnet publish` 直接失败：
```
error CS0234: 命名空间"MicaSetup"中不存在类型或命名空间名"Core"
```

**根因**：C# 项目默认通配 `**/*.cs`，把 `setup\inject\` 也扫进去了。
（`.dist\` 之前没事，是因为 **MSBuild 默认排除点开头的目录**。）

**修法**：双重保险
1. 目录改成点开头：`setup\.inject\`
2. `VrcTool.csproj` 里显式排除：
```xml
<ItemGroup>
  <Compile Remove="setup\**" />
  <Page Remove="setup\**" />
  <None Remove="setup\**" />
  <Resource Remove="setup\**" />
  <EmbeddedResource Remove="setup\**" />
  <Content Remove="setup\**" />
</ItemGroup>
```

### D2 `param()` 块里插语句导致语法错误

**现象**：批量替换 `[string]$OutDir = 'C:\vrchat-bypass'` 时，把 `if (-not $OutDir) {...}` 也插进了 `param()` 块里。

**修法**：`param()` 里只留声明，逻辑挪到块外

```powershell
param(
    [int]$TopN = 40,
    [string]$OutDir = ''          # ← param 里只给空值
)

$RootDir = if ($env:VRCTOOL_ROOT) { $env:VRCTOOL_ROOT } else { Split-Path $PSScriptRoot -Parent }
$DataDir = if ($env:VRCTOOL_DATA) { $env:VRCTOOL_DATA } else { Join-Path $RootDir 'data' }
if (-not $OutDir) { $OutDir = $DataDir }        # ← 逻辑在块外
```

### D4 ⚠️⚠️ 脚本改了一份忘了另一份

**现象**：我把镜像列表改到 `dist\scripts\install.ps1`，但**编译进 EXE 的是 `wpf\Scripts\install.ps1`** —— 结果那一次交付的安装包里修复根本没生效。

**根因**：`VrcTool.csproj` 里是 `<EmbeddedResource Include="Scripts\*.ps1" />`（相对 `wpf\`）。

**修法**：见 `ISSUES.md` #7（建议在构建脚本里加自动同步 + 一致性断言）。

**检查命令**：
```powershell
foreach ($f in Get-ChildItem '<包根>\dist\scripts' -Filter *.ps1) {
    $a = (Get-FileHash $f.FullName -Algorithm MD5).Hash
    $b = (Get-FileHash "<包根>\src\app\Scripts\$($f.Name)" -Algorithm MD5).Hash
    if ($a -ne $b) { "不同步: $($f.Name)" }
}
```

### D7 自包含单文件首次启动慢

**现象**：65 MB 的自包含单文件 EXE，首次启动要解压到临时目录，**要等 5~15 秒**。

```powershell
    if ($p.Count -gt 0) { "第 $($i*5) 秒启动成功"; break }
}
```

## E. 通用教训

| # | 教训 |
|---|---|
| 1 | **量数据，别猜。** 截图上看不出来的东西，往临时目录写日志打印 `ActualHeight` / `DesiredSize` / `VerticalAlignment` |
| 2 | **第三方工具报错，先扒它的二进制字符串**，看它到底执行了什么命令（`vswhere` 就是这么查出来的） |
| 3 | **PowerShell 5.1 的编码坑**：`.ps1` 要带 BOM，`.json` 不要 BOM |
| 4 | **多行字符串替换前先归一化换行符**（`\r\n` vs `\n`），这个坑踩了两次 |
| 5 | **不要用正则批量改 XAML** |
| 6 | **归属不清的失败先排查"我改的东西有没有真的生效"** —— 脚本双份、增量编译、缓存，都骗过我 |
| 7 | **提权进程的窗口，只能从提权进程操作**（杀进程、UIA 查询都一样） |
| 8 | **DPI 虚拟化**：坐标系统要统一，要么全部物理，要么全部虚拟 |
| 9 | **不要在项目目录下放构建用的 `.cs` 文件**（会被 C# 通配符扫走），用点开头的目录 |
| 10 | **清理提权通道的注册表项**（`HKCU:\Software\Classes\ms-settings`），必须在 `finally` 里 |
