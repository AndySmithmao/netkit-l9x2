Настольная программа для Windows, улучшающая качество сетевого соединения VRChat. Включает два ядра —
winws (обход DPI из zapret) и mihomo (Clash.Meta), — а также путь оптимизации hosts, не требующий прокси.
Написана на WPF / .NET 10, для запуска нужны права администратора.

Текущая версия 0.0.1-beta, интерфейс и настройки могут меняться.

## Какую задачу решает

Качество соединения VRChat зависит от маршрута до серверов Photon. В некоторых сетях встречается следующее:

- DNS возвращает IP низкого качества, растут задержка и потери пакетов;
- международный маршрут сильно петляет, и один переход добавляет более 100 мс;
- на части маршрута есть вмешательство DPI, проявляющееся как срыв рукопожатия или частые переподключения.

Для первых двух случаев программа сканирует диапазоны Cloudflare и CloudFront, измеряет задержку и скорость
загрузки и записывает лучшие IP в hosts. Для третьего случая и когда трафик нужно выводить через другой регион,
проксирующее ядро распределяет его по правилам. Оба подхода работают по отдельности или вместе.

## Три способа использования

**Только оптимизация hosts.** Откройте «Один клик» и нажмите старт. Программа проверит окружение,
просканирует диапазоны, измерит задержки и скорость загрузки, затем покажет список кандидатов;
выберите IP, и он будет записан и проверен. Подходит тем, кто не хочет использовать прокси.

**С прокси-узлами.** Вставьте подписку Clash на странице «Подписка», выберите узел на странице «Узлы»,
затем запустите mihomo на странице «Ядра». Если нужен прокси для всего трафика, включите TUN и перезапустите
mihomo. Перед выбором узла можно сравнить их на странице «Ping».

**Обход DPI через winws.** Запустите winws на странице «Ядра»; используется встроенный профиль desync.
Если прежняя версия регистрировала службу `VRChatBypass`, сначала выполните «Перенос старой службы»,
иначе два фильтра будут конкурировать за один дескриптор.

## Страницы

Левая навигация сгруппирована по назначению. «Один клик» — автоматический сценарий, описанный выше.
«Обслуживание» содержит установку, удаление и диагностику. «Процедуры» — четыре отдельных шага:
полное сканирование, измерение задержки, измерение скорости загрузки, выбор из списка.

Раздел «Ядра и прокси» состоит из четырёх страниц:

- Ядра: запуск, остановка и перезапуск winws и mihomo, текущие версии, диагностика, перенос старой службы
- Подписка: импорт и обновление ссылки подписки; после сохранения mihomo запускается автоматически
- Узлы: список узлов в виде карточек, переключение по клику, пакетное измерение задержки, переключатели TUN и режима прокси
- Ping: для указанного IP или имени хоста выполняется TCP + TLS рукопожатие через каждый узел, сортировка по возрастанию задержки

На странице настроек — тема, масштаб интерфейса и пункт обновления.

## Почему Ping не использует ICMP

mihomo обрабатывает ICMP всегда как DIRECT, ядро не может передать ICMP прокси.
При измерении одного и того же IP через узлы США, Японии и Гонконга получается около 172 мс во всех случаях —
это локальный прямой маршрут, и число бесполезно. Поэтому «Ping узла» здесь — TCP-рукопожатие,
а именно полное TLS-рукопожатие с портом 443 для получения реального времени оборота.
Для одного из IP Google: Гонконг 87 мс, Япония 80 мс, США 551 мс — разница достаточная.

Обратное тоже верно: если цель отвечает только на ICMP или собственный протокол UDP
(так ведут себя игровые серверы Photon), задержку по узлам измерить нельзя, виден только прямой маршрут.

## Как записывается hosts

Выбранные IP вносятся в системный файл hosts между парой маркеров; при удалении записи чистятся по маркерам.

```
# ===== VRChat-bypass BEGIN =====
104.18.26.36  example.com
# ===== VRChat-bypass END =====
```

Кандидаты берутся из 5956 диапазонов /24 Cloudflare и 16552 диапазонов /24 CloudFront,
затем отбираются по ICMP и TLS и измеряются несколькими раундами задержки и реальной загрузкой.

## Почему ядра не являются службами Windows

В ранних версиях winws регистрировался как служба Windows. После `sc stop` объекты фильтра WFP
не освобождались, и следующий запуск завершался ошибкой `FWP_E_IN_USE 0x8032000A`,
восстановить работу можно было только перезагрузкой. Сейчас ядро работает как дочерний процесс,
управляемый приложением, и очищается по пути исполняемого файла; три цикла остановки и запуска проходят без ошибок.

- winws перехватывает и изменяет пакеты через WinDivert, используя встроенный профиль desync
- mihomo отвечает за узлы подписки и маршрутизацию по правилам; режим TUN требует прав администратора

## Обновления

Примерно через пять секунд после запуска проверяются версии приложения и обоих ядер; при наличии новой
версии появляется диалог. Отказ пропускает проверку до следующего запуска. На странице настроек есть
и ручная проверка.

Обновление приложения скачивает установщик, сверяет SHA256, запускает его и завершает работу.
Обновление ядра сначала переименовывает старые файлы в `.bak`, затем заменяет их и пробует запустить;
при неудаче выполняется откат.

Результаты кэшируются на шесть часов. Анонимный API GitHub допускает 60 запросов в час,
а одна проверка при запуске требует трёх, поэтому частые запуски упираются в лимит.
Ручная проверка кэш игнорирует.

## Сборка из исходников

Нужен .NET 10 SDK; для установщика — MSBuild из Visual Studio 2022 или 2026.

```
git clone https://github.com/AndySmithmao/netkit-l9x2.git
cd netkit-l9x2

dotnet build src\app\VrcTool.csproj -c Release

powershell -File src\setup\build-installer.ps1
```

Скрипт сборки сначала запускает `tools\verify.ps1`: проверяются кодировки файлов (всё с не-ASCII должно быть
UTF-8 с BOM), синтаксис скриптов, совпадение двух наборов скриптов, остатки жёстко заданных путей,
список встроенных ресурсов и согласованность версий. Любая ошибка прерывает сборку.

### mihomo.exe нужно подготовить

`src\drivers\mihomo.exe` занимает около 61 МБ и в репозиторий не входит. Перед сборкой скачайте
`mihomo-windows-amd64-vX.Y.Z.zip` у upstream, распакуйте `mihomo.exe` в `src\drivers\` и создайте
`mihomo.VERSION.txt` (например, `Mihomo Meta v1.19.32 windows amd64`) — обновлятор сравнивает версию по нему.

winws.exe, cygwin1.dll и оба файла WinDivert входят в репозиторий.

### Частые проблемы сборки

`error CS1566: не удалось прочитать ресурс WinDivert64.sys` означает, что файл занят работающим winws.
Остановите winws или удалите `obj` и `bin` и пересоберите.

Если `verify.ps1` сообщает об отсутствии BOM, запустите `tools\fix-bom.ps1`.

Установщик размером два-три мегабайта означает, что на этапе упаковки mica полезная нагрузка не попала внутрь.
Обычная причина — суффикс в номере версии (`0.0.1-beta`), makemica принимает только числовые версии.
Скрипт сборки срезает суффикс автоматически, но при ручном вызове об этом нужно помнить.

## Известные ограничения

ICMP нельзя проксировать, поэтому измерение по узлам опирается на TCP-рукопожатие,
а цели, отвечающие только на ICMP, измерить невозможно.

Анонимный API GitHub допускает 60 запросов в час; частые запуски могут упереться в лимит,
смягчает это шестичасовой кэш.

mihomo занимает порты 7891 и 9097. Если другой экземпляр уже запущен, возникает конфликт портов:
подписка импортируется успешно, но список узлов пуст.

Поддерживается только Windows x64 из-за WinDivert и WPF.
